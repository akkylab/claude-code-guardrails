# 守れない範囲

塞げていないと分かっている経路を、ここに書き出します。

**塞いだつもりの範囲を実際より広く見積もると、その隙間で事故が起きます。**「フックを入れたから安全」と思い込むことのほうが、フックが無いことより危険です。

## 仕組みの上で届かないもの

| 範囲 | なぜ守れないか |
|---|---|
| あなたが自分でターミナルへ打つコマンド | フックはClaude Codeがツールを呼ぶときにだけ走ります。あなたの手打ちには関与しません |
| Claude Codeのシェルモード（`!` で打つ形） | 同じ理由です。出力はそのまま会話へ入ります |
| 終了コードが0以外で終わったコマンドの出力 | 出力を差し替える手段がハーネス側にありません |
| フックを組み込む前に起きたこと | 過去のログに残った秘密は、あとから消せません |

## 判定の性質として抜けるもの

### コマンドの書き換えで回避できます

判定は文字列のパターンで行います。同じ操作を別の書き方で表現されると、抜けます。

```
止まります      cat .env
抜けます        cat .e''nv
抜けます        cat $(echo .env)
```

これは直せる種類の穴ではありません。シェルの展開を完全に追うには、シェルそのものを実装することになります。**このフックは、うっかりを止めるためのものであって、意図した回避を防ぐためのものではありません。**

### 知らない危険は止められません

`guardrails/patterns.py` に書いてあるものだけを止めます。新しい危険なコマンドや、まだ知られていない秘密の置き場は、書き足すまで素通りします。

見つけたら、そのファイルへ足してください。同時にテストも1件足してください。**足すだけでは守りになりません。止まることをテストで示して初めて守りになります。**

## 秘密の保護として足りていないもの

このフックが見るのは、Claude Codeが実行しようとする操作だけです。次の経路は対象外です。

| 経路 | 何が起きるか | どう塞ぐか |
|---|---|---|
| HTTPライブラリのログ | `httpx` がURLをそのままINFOログへ出します。クエリにAPIキーを載せていると記録されます | ログの設定でHTTP系ロガーをWARNING以上に固定します |
| エラー追跡サービス | Sentryは `send_default_pii=False` でもクエリ文字列を保存します | `before_send_transaction` でクエリを削ります |
| 例外のメッセージ | HTTPのエラーは、完全なURLを含んだ文字列を持つことがあります | 例外から完全なURLを除いてから記録します |

これらはアプリ側で塞ぐものです。このフックの守備範囲の外にあります。

## それでも入れる価値があるのはなぜか

守れない範囲を並べると、意味が薄いように見えるかもしれません。ですが、実際に起きる事故のほとんどは意図した回避ではなく、うっかりです。

- 中身を確かめようとして `.env` を読む
- 作業をやり直そうとして `git reset --hard` を打つ
- 認証の状態を見ようとして `gh auth token` を打つ

どれも悪意はなく、その瞬間には自然な操作に見えます。**人の注意力は、この種の「自然に見える操作」に対しては働きません。**機械だけが、毎回同じ強さで止められます。
